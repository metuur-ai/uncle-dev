01

What is Uncle Dev?

SYS-01

Uncle Dev transforms chaotic AI agents into disciplined Senior Staff Engineers by overriding default behaviors with a structured, step-by-step workflow.

VANILLA AI

Unstructured code generation. Random hallucinated logic.

UNCLE DEV

Sequential verification. Spec-driven engineering.

The Problem

When a developer says, "Build me a login page," a vanilla AI agent will immediately output HTML, CSS, and database queries. It guesses the architecture, guesses the edge cases, and often hallucinates business logic.

The Solution: SDD

  1. Alignment Before Execution: SDD mandates that the AI agent must write and agree upon a specification document with the developer before writing code.
  2. Context Retention: SDD externalizes memory into markdown files. The AI can re-read these documents to instantly regain total context.
  3. Controlled Scope: The agent is required to break the specification down into a strict, atomic checklist.
  4. Anti-Rationalization: Uncle Dev skills contain specific "anti-rationalization tables" that forcefully override sloppy habits.

1. The openspec/specs/ Directory

This directory serves as the Project Truth. It contains the living documentation of how the application works. Before an agent builds a new feature, SDD forces it to read this.

2. The openspec/changes/ Directory

This folder stores the lifecycle of a new feature undergoing development. When you trigger /uncle-dev-spec, the agent outputs artifacts here.

04

DEVLOCAL Sandbox

SYS-04

The .devlocal/ workspace is designed to be excluded from version control.

openspec/ Canonical Truth Version Controlled (Git) Entire Engineering Team
/// VS ///
.devlocal/ Private Execution Plans Excluded (.gitignore) AI Scratchpad Layer

1. Private Execution Plans

When you execute /uncle-dev-plan, the AI agent will break down the macroscopic user-story tasks into granular steps. Once the task is complete, this temporary checklist becomes obsolete.

2. Debugging and Logs

During the Verify phase, the AI agent might output massive command line logs, performance profiles, or error tracebacks. Storing these keeps the root directory perfectly clean.

05

Idea to Deploy

SYS-05

The Uncle Dev lifecycle enforces a strict sequence of events. Each phase must be completed before moving to the next.

01 REFINE /idea-refine
02 DEFINE /spec
03 PLAN /plan
04 BUILD /build
05 VERIFY /test
06 REVIEW /review
07 SHIP /ship
  • Phase 1: Idea Refinement - Use the skill to challenge assumptions and settle on a minimum viable product configuration.
  • Phase 2: Define (/uncle-dev-spec) - The AI agent authors a strict spec isolating the architecture. Look for human approval.
  • Phase 3: Plan (/uncle-dev-plan) - Decompose the approved spec into shared story-level tasks (tasks.md) and execution checklists.
  • Phase 4: Build (/uncle-dev-build) - Execute code implementation one vertical slice at a time.
  • Phase 5: Verify (/uncle-dev-test) - Write tests. Pivot to debugging skills to scientifically fix bugs.
  • Phase 6: Review (/uncle-dev-review) - Scans the diff using the code-review framing.
  • Phase 7: Ship (/uncle-dev-ship) - Reconcile changes to openspec/specs/ and prep for deployment!
06

Phase Prompts

SYS-06

Phase 1: Define

/uncle-dev-spec We need to build a new feature: [Feature Description]. Key constraints: 1. [Constraint 1] Create the proposal and design specs in openspec/changes/.

Phase 2: Plan

/uncle-dev-plan Based on the approved design for [Feature], break this down into actionable, atomic tasks. Put the high-level tasks in OpenSpec, and initialize a scratchpad in .devlocal/.

Phase 3: Build

/uncle-dev-build Let's implement Task [X] from our execution plan. Please slice this implementation thinly.

Phase 4: Verify

/uncle-dev-test Based on the code slice we just built, implement tests via the Testing Pyramid strategy. Focus on edge cases. Run tests.

Phase 5: Review

/uncle-dev-review Act as a Senior Staff Engineer and perform a 5-axis review heavily on performance, readability, and security gaps.

Phase 6: Ship

/uncle-dev-ship The feature is complete. Reconcile our updates from the change artifact back into openspec/specs/.
