Strict Context Boundaries

OpenSpec provides a strict directory structure designed to separate the current state of a project from chaotic works-in-progress. The AI is forced to read this before executing changes.

openspec/
specs/ ← Project Truth (Current architecture, models, APIs)
changes/ ← Work-in-progress features
feat-shopping-cart/
proposal.md - What & why
design.md - DB tables, APIs
tasks.md - Atomic checklist

1.

Idea Refinement

Using the uncle-dev-idea-refine skill, challenge assumptions, discover risk factors, and settle on a minimum viable product configuration before touching code.
2.

Define

/uncle-dev-spec
The agent authors a strict proposal.md and design.md in openspec/changes/. The human reviews architecture and schema before proceeding.
3.

Plan

/uncle-dev-plan
The agent decomposes the approved spec into shared story-level tasks (tasks.md) and initializes an execution checklist in .devlocal/.
4.

Build

/uncle-dev-build
Code implementation happens one vertical slice at a time. Automatically kicks off stack-specific sub-skills (UI engineering, API design, etc).
5.

Verify

/uncle-dev-test
AI writes unit, integration, and e2e tests. If they fail, it pivots to scientific debugging rather than blindly guessing syntax updates.
